# 自动烧录与 OTA 压测

## 启动

在项目根目录执行：

```bash
pip install PySide6 pyserial
python OTAtest/autoburn.py
```

程序需要保留项目根目录的 `protocol_profiles.py` 和 `config_manager.py`。不会导入或启动原日志采集主窗口。

## 自动烧录

1. 在主界面选择用于还原版本的 BAT/CMD、模式 1～3、继电器串口和两路通道。
2. 使用常开触点：ON 表示供电或短接，OFF 表示断电或释放短接。
3. 在“设置”中调整时序与超时。BAT 必须支持标准输入选择模式，并将日志输出到当前进程。
4. 烧录成功后，程序确认短接已断开，断电并等待默认 200ms，再重新上电。实际断电时长还包括串口查询确认耗时。

## 项目标识设置

四类标识统一在主界面的 **设置 → 时序、日志编码与标识…** 修改，点击确定保存，下次启动沿用。取消会恢复修改前的值，关键词不允许为空。

| 标识 | 默认值 | 用途 |
| --- | --- | --- |
| 烧录开始 | `core (int)message` | BAT 自动烧录进入烧录的判断 |
| 烧录结束 | 以下三行序列 | 普通自动烧录及 OTA 中的烧录还原完成判断 |
| OTA 升级结束 | `startBurn success` | 测试包、标准包完成判断，以及延时掉电扫描的结束判断 |
| 进入 Recovery | `dwc` | 重启后的 Recovery 观察 |

默认烧录结束序列：

```text
0:0:1:6:100;
0:0:1:6:100;
0:0:0:8:0;
```

- 自定义烧录标识按文本包含匹配、区分大小写，不是正则。结束标识可填一个关键词，也可每行填一个关键词，按日志行顺序逐条匹配；普通无关日志不打断顺序。
- 默认烧录开始标识保留原先不区分大小写、允许空白变化的协议匹配；默认结束序列保留严格消息字段判定，时间戳及普通日志不影响判断，其他协议消息会打断序列。
- OTA / Recovery 关键词按文本包含匹配，不区分大小写，允许跨串口读取块；不是正则。两者统一供测试包、标准包和掉电测试使用，无须在 OTA 弹窗重复设置。
- 请填写项目实际输出的、足够明确的关键词，避免使用过短或常见文本导致误判。当前 Recovery 默认保持现有代码的 `dwc`，其他项目可改为 `rootfs error` 等实际标识；未检出不代表启动正常。

## 紧凑布局与日志全屏

烧录配置中的继电器串口、波特率、电源/短接通道和烧录模式在同一行。继电器按钮“−”表示接通、“O”表示断开，悬停显示通道和操作说明，右侧查询按钮跨两行。

拖动配置区与日志区之间的水平分隔条，可上下调整日志高度；继续向上拖到配置区折叠时进入日志全屏。也可点击“全屏日志”或按 F11；按 Esc、F11 或“退出全屏”返回。全屏仍保留停止任务按钮，退出后恢复配置区与原窗口状态。

OTA 压测从“模组日志编码”至“连续找不到 OTA 串口多久后重启”的参数集中在默认折叠的“高级设置”，展开后每行两项。步骤选择与掉电选项保持直接可见，折叠不改变参数值。

## 日志自动归档

界面日志分为两个并排区域，可拖动中间分隔条调整宽度，同时实时刷新：

- **操作日志**：OTA 流程、继电器、BAT 输出、Recovery 检测提示、逐轮结果与错误。
- **模组日志**：日志串口的模组输出（带“模组日志 |”前缀）。

两个区域支持独立上滑查看历史：向上滚动后暂停该区域的自动跟随，新日志仍持续接收、显示并归档，不会强制跳到底部；另一块日志不受影响。点击各自右上方的“回到最新”，或手动滚到最底部，会恢复自动跟随。

两个区域各自只显示最近 20000 行，互不挤占显示历史。暂停跟随不会取消该上限，超出上限被移除的旧行请通过“打开归档”查看。完整日志仍按收到的先后顺序统一归档，在分流显示前实时写入磁盘，每 20000 行自动切换到下一个文件，不覆盖已有分段：

```text
OTAtest/logs/autoburn_日期_时间_唯一后缀/
    part_00001.log
    part_00002.log
    ...
```

- 包含普通烧录、继电器查询/手动操作、OTA 压测发送到界面的全部日志，使用 UTF-8 编码。
- 从第一条日志开始保存，每次追加后刷新文件；不足 20000 行的最后一段也会保存，无须等到达到上限。
- “保存日志”左侧的“打开归档”打开当前会话目录（尚无日志时打开归档根目录），悬停可查看路径。“清空日志”同时清空两区显示，不删除归档；“保存日志…”将两区当前显示内容按“操作日志 / 模组日志”分段导出到同一个文件。
- 写入失败时，“打开归档”变为红色“归档失败 · 打开目录”，悬停查看原因，界面仍可显示日志，但本次窗口不再继续自动归档。请检查磁盘空间和目录权限，手动保存当前显示日志后重新打开工具。
- 不自动删除历史归档，长时间压测时请定期检查磁盘空间。每次启动使用独立目录。

OTA 压测另有结果目录中的完整 `session.log` 和 `rounds.jsonl`，与这里的界面日志归档互不替代。

## OTA 压测

从顶部“功能 → OTA 压测”进入。三个步骤可独立勾选，掉电为测试包步骤的可选参数，详见下方“统一 OTA 压测：步骤组合与可选掉电”。以下流程说明以三个步骤均选中为例。

### 必填配置

- **待压测文件 / 文件夹**：选择一个非空 `.bin`，或递归包含多个 OTA `.bin` 的文件夹。文件按相对路径排序；目录中不要混入非 OTA 的烧录 BIN。
- **固定标准 OTA 包**：默认每轮测试包完成后升级同一个标准包。取消“每轮执行标准包升级”可省略此步骤。
- **OTA 通信串口**、**模组日志串口**及各自波特率。它们和继电器串口必须互不相同，并关闭其他占用串口的软件。
- **压测轮数**：包数量不足时，从第一个重新循环；每轮只使用一个测试包。
- **协议组 / 模态**：内置 DSM/KDS，或原上位机保存的自定义协议组。自定义组的“跳过 OTA 头”设置也会复用。

OTA 使用原上位机相同的进入 OTA、文件头和分包协议，包含 MD5、长度和 XOR 校验，每包等待响应后再发下一包。**当前保持所选波特率，不发送切换波特率指令**，必须选择模组实际波特率。包数据仅作为二进制读取，不解包或执行。

开始前先释放烧录短接、确保电源接通，并等待配置的启动时间。启动前的这段日志不计入测试包的 Recovery 检测。

每个 OTA 阶段会记录日志监控切换、开始打开串口、文件读取和发送准备等步骤。日志监控锁等待最多 2 秒。OTA 串口打开由独立线程执行，单次驱动调用等待最多 5 秒（同时受重连剩余时间约束）；读取用的 `timeout` 本身不限制 Windows 打开串口的耗时。升级指令发送前，若驱动打开超过 5 秒不返回，也会执行电源恢复重启，不要求系统 COM 列表中端口消失。后台驱动调用无法强制终止；重启后等待原打开操作结束，迟到的连接自动关闭，清理完成后才重新打开，不叠加打开线程。若原操作仍未结束，至少再等待 5 秒才允许下一次恢复重启；与端口缺失恢复共用次数上限和重连总等待时间。次数设为 0 时不自动重启，总等待超时后报错退出。

每次 OTA 成功后、断电之前会关闭 OTA 通信串口，下一次升级前重新打开。Windows 重新上电后可能需要时间恢复 COM 设备：打开失败时每秒重试，并重新查询系统 COM 列表。若连续 5 秒未枚举到所选 OTA 串口，自动确认短接释放、断开模组电源，按“OTA 重启断电间隔”（默认 500ms）等待后重新上电，再等待串口枚举。每次 OTA 连接默认最多恢复重启 2 次；若串口存在但被占用，或查询 COM 列表本身失败，则不自动断电。

压测弹窗可调整“连续找不到 OTA 串口多久后重启”“每次串口连接最多自动重启次数”（0 禁用）及“OTA 串口重连总等待上限”（默认 30 秒，包含恢复重启耗时）。总时间不足以完成断电间隔并至少再等待 1 秒时，不再触发新重启。自动恢复只在升级指令发送前生效，不用于正在传输或烧写的阶段，不计入 Recovery 统计。重连期间可停止，不会重发已经升级完成的包。若重新枚举成不同 COM 号，不会擅自连接其他设备，超时后请检查设备管理器并重新选择串口。

### 每轮流程

1. OTA 升级当前测试包。
2. 等待日志串口输出设置中的 OTA 升级结束标识（默认 `startBurn success`）。数据发送完成或通信 ACK 不是升级完成标志。
3. 默认等待 2 秒后断电，保持默认 500ms，再重新上电。等待时间可配置，有最小值限制以留出继电器切换间隔。
4. 从重新上电开始观察日志，默认 15 秒；发现设置中的 Recovery 关键词（默认 `dwc`）立即输出“进入 Recovery”。关键字允许跨串口读取块匹配。
5. 如果启用了标准包，升级固定标准包，同样等待成功、重启、观察并记录。
6. 执行主界面配置的 BAT 自动烧录，恢复上一版本；完成后重启，默认等待启动 15 秒。
7. 开始下一轮，切换到下一个测试 BIN。

进入 Recovery 会记录结果并继续后续标准包或烧录流程。观察窗口内未出现设置中的 Recovery 关键词 **不代表已验证启动正常**。通信、升级、日志串口或烧录错误将终止本次压测，不自动跳过故障继续断电。

### 结果与停止

主界面顶部实时显示“已完成轮数 / 总轮数”、当前轮次，以及测试包和标准包各自进入 Recovery 的轮数。每个 OTA 阶段完成观察后更新对应计数；只有烧录还原和启动等待均完成才计入已完成轮数。标准包步骤关闭时显示“已跳过”，不将其误判为未进入 Recovery。

压测结束（包含失败或停止）后，输出窗口先集中列出逐轮结果，每轮一行，包含包路径、两种包的 Recovery 结果、还原结果和中断阶段，再输出总统计。结果同样写入完整会话日志。

在所选结果目录创建唯一会话子目录，自动保存：

- `session.log`：完整操作日志、BAT 输出和模组串口日志；不受界面最近 20000 行的显示限制影响。
- `rounds.jsonl`：每轮的测试包、标准包、Recovery 检测、完成状态和错误原因。一行对应一轮。

使用主界面的“停止”结束压测。程序关闭本次 BAT 和串口，并尝试释放烧录短接；模组电源保持停止时状态。若在断电间隔停止，电源可能保持断开，可在操作结束后手动接通。

四路手动按钮在压测期间仍可使用，指令通过已有继电器串口排队执行，但人工切换可能中断升级，后续自动时序也可能覆盖手动状态。重启断电及 Recovery 观察区间暂不执行排队的手动指令，避免改变观察结果。

## 统一 OTA 压测：步骤组合与可选掉电

统一从“功能 → OTA 压测…”进入，不再提供单独的掉电菜单。三个步骤至少选择一个，按固定顺序执行：

1. 测试包升级及 Recovery 判断。
2. 标准包完整升级及 Recovery 判断。
3. 模组自动烧录（使用主界面 BAT、模式和时序）。

不选测试包时无需测试 BIN；不选标准包时无需标准 BIN；不选自动烧录时无需 BAT。只选自动烧录时无需 OTA/模组日志串口，也不会打开它们。继电器串口及两路通道配置仍需要。统一配置沿用 `ota/` 设置，原独立掉电配置不自动套用，以免意外开启掉电。

两个掉电选项均不选时，每轮只执行一次所选步骤；勾选掉电时，每轮扫描梯度，每个点均执行所选步骤。取消步骤 1 会自动取消并禁用掉电选项，标准包和自动烧录步骤不注入掉电。首次启动前确认模组状态；不选步骤 3 时不会还原基线，下一点使用上一点留下的版本。

步骤 1 可选以下一种或两种掉电方式：

- **传输进度掉电**：按已确认数据包数计算进度，梯度 10% 时测试 10%、20%……90%，不含 0%/100%。梯度 30% 时测试 30%、60%、90%。在第一个达到目标的包确认后掉电，受分包粒度影响，实际百分比可能略大于目标；如果目标只能落到最后一个包，报错而不是在 100% 注入掉电，应减小分包大小。
- **100% 后延时掉电**：从最后一个数据包确认时起计时，每个独立测试点使用 n、2n、3n……ms。某次设置中的 OTA 升级结束标识先于断电指令到达，则不再注入掉电，正常等待后重启观察，完成已勾选的后续步骤后结束该轮延时扫描。扫描封顶到“等待升级结束标识上限”，始终未提前检测到成功则报错，不无限增加延时。

启用掉电时每点执行：测试包 → 目标点掉电 → 重新上电观察 Recovery → 标准包完整升级（若选中）→ BAT 还原（若选中）→ 下一个测试点。两种均选时先扫描传输进度，再扫描延时。一轮代表同一个包扫完全部选定梯度；下一轮选择下一个文件，文件不足时循环。因延时扫描的终点取决于成功标志，实际测试点总数运行前未知。

定时断电先发送继电器 OFF 指令再查询确认，避免前置查询推迟断电。记录目标值、实际确认包进度、从触发基准到软件调用串口写入 OFF 指令的时间；**这不是物理触点断开时间**，Windows 调度、USB/串口和机械继电器延迟均会引入误差，不保证毫秒级精度。测试期间禁用人工继电器控制，避免干扰实验；停止/异常不继续执行标准包或自动还原，断电时停止将保持断电。

顶部显示完成的梯度轮数、已记录测试点及两类 Recovery 次数；完整日志与 `rounds.jsonl` 保存每个点的目标、掉电指令是否已发、OFF 状态是否确认、Recovery、标准升级和还原结果。指令已发但确认失败/停止时仍保留发送时间，Recovery 观察未完成时标为“未完成 / 未检测”，不计为观察通过。Recovery 使用“设置”中的监控关键词（默认 `dwc`），没有检出不代表启动正常。

## 离线验证

```bash
python -m unittest discover -s OTAtest -p "test_*.py" -v
```

测试使用模拟串口和后台 Qt 平台，不执行真实 BAT 或控制真实继电器。实际设备的 OTA 响应、波特率、BAT 行为和启动时间仍需硬件联调确认。
